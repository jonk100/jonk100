The `Skeleton` suite is used to construct "ghost" layouts that represent content while it is being fetched. By mimicking the geometric shape of the eventual data (like text lines or circular avatars), we reduce the user's perceived latency and eliminate distracting layout shifts as items pop into view.

### Hardware-Accelerated Shimmers
Rather than animating the background color of the element directly (which can cause expensive browser repaints), our shimmer effect utilizes a linear-gradient background moved via `background-position`. This allows the animation to be offloaded to the browser's GPU, ensuring that even pages with dozens of loading skeletons maintain a smooth 60fps frame rate without taxing the CPU.

### Usage Blueprints

#### Common: Content Mockups
Compose skeletons to represent standard content blocks:

### Compound Component: SkeletonGroup
The `SkeletonGroup` component acts as a high-level conditional switch. It allows you to define both a "loading" state (using skeletons) and a "ready" state (the actual component) within the same block, simplifying state management in complex views.

<ComponentPreview
  title="Skeleton Conditional Switching"
>
  <div style="width: 100%; display: flex; justify-content: center; text-align: left;">
    <SkeletonGroup loading={true}>
      <Stack gap="md" slot="loading">
        <Skeleton width="120px" height="1.5rem" />
        <Skeleton height="3rem" />
      </Stack>
      <Paper layer={1} padding="md">
        <Text type="h5">Data Loaded</Text>
        <Text type="body-sm">This content is only visible when loading is false.</Text>
      </Paper>
    </SkeletonGroup>
  </div>
</ComponentPreview>
