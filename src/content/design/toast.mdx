The `Toast` system provides a lightweight way to deliver success, error, or status feedback to users without interrupting their current workflow. Unlike persistent `Alert` components, toasts are transient and stack vertically in a fixed global container.

## The Global API Strategy
To ensure that feedback can be triggered from anywhere in the codebase—including deep within client-side logic—we expose a singleton `toast` instance on the `window` object. 
1. **ToastProvider**: Must be included once in the root layout. It manages the fixed container and CSS stacking context.
2. **TypeScript Registry**: The system includes a `toast.notify()` method that supports full TypeScript type safety for theme selection and durations.
3. **Hardware Acceleration**: Entry animations utilize GPU-bound CSS transforms (`translateX`) to ensure stutter-free presentation even during heavy page loads.

## Usage Blueprints

### Common: Feedback Triggers
Use the global API to signal the results of user actions, such as saving data or copying text:

<ComponentPreview
  title="Action Feedback Showcase"
>
  <div style="width: 100%; display: flex; justify-content: center;">
    <Inline gap="md">
      <Button theme="success" onclick="toast.notify({ message: 'Blueprint saved successfully.', theme: 'success' })">Success Toast</Button>
      <Button theme="danger" onclick="toast.notify({ title: 'Critical Error', message: 'Unable to sync registry.', theme: 'danger' })">Error Toast</Button>
    </Inline>
  </div>
</ComponentPreview>

Demonstrates utilizing longer durations and accent themes for high-priority informational notifications:
