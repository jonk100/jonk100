The `Card` component is a high-level container designed to organize information into digestible blocks. It extends the `Paper` primitive, inheriting its elevation and framing capabilities while providing a structured internal sub-component architecture (`Header`, `Content`, `Footer`).

### Composite Architecture
To ensure layout consistency across varied content types (like project tiles, blog snippets, or user profiles), the Card uses a nested component system. This allows for rigid padding controls and semantic segmentation:
1. **CardHeader**: Handles titles and status badges with standardized top-padding.
2. **CardContent**: The main body area with generous horizontal gutters.
3. **CardFooter**: A dedicated action row at the bottom, automatically aligned with flexbox.

### Usage Blueprints

#### Common: Feature Information Block
Standard implementation for displaying a title, body text, and an primary action:

<ComponentPreview
  title="Standard Feature Card"
>
  <div style="width: 100%; max-width: 360px; margin: 0 auto;">
    <Card layer={1} bordered>
      <CardHeader>
        <Text type="h5" style="margin:0;">System Diagnostic</Text>
        <Badge theme="success" size="xs">Operational</Badge>
      </CardHeader>
      <CardContent>
        <Text type="body-sm" tone="subtle">All core telemetry streams are reporting nominal. No critical failures detected in the local registry.</Text>
      </CardContent>
      <CardFooter>
        <Button size="sm" theme="primary">View Logs</Button>
        <Button size="sm" theme="ghost">Ignore</Button>
      </CardFooter>
    </Card>
  </div>
</ComponentPreview>
