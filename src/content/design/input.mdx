The `Input` component acts as our primary visual container for user form text entry, wrapping the standard HTML `<input>` element inside a structured label/error layout. Standardizing this component ensures we don't duplicate boilerplate accessible layout structures, coordinates inline helpers, and provides a unified visual baseline for all form fields.

### Dynamic ARIA & Content Auto-Sizing
To deliver a premium user experience and maintain strict accessibility standards, we built in two core architectural features:
1. **Dynamic ARIA Descriptors**: The component automatically generates unique field IDs. When an `error` or `hint` is present, it dynamically maps the input's `aria-describedby` attribute to the corresponding message ID node. This alerts screen readers to validation updates in real-time.
2. **Modern CSS Auto-Sizing**: The input field utilizes the modern CSS `field-sizing: content` property. This allows the text field to automatically expand or contract horizontally based on the user's typed content, eliminating the need for heavy JavaScript keystroke event listeners.

### Usage Blueprints

#### Common: Form Field Variations
Instead of manually declaring labels and error wrappers for every text box, you can pass theme and constraint properties. This consolidates standard configurations inside a single visual preview showcase:
