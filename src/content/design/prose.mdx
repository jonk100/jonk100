The `Prose` primitive acts as a critical bridge between dynamically generated content and our rigid design system. When authors write in Markdown or pull strings from a CMS, the output resolves as naked HTML (`<h1>`, `<p>`, `<strong>`). Since we do not globally style raw HTML tags to prevent component cross-contamination, those blocks render with default, often broken, browser aesthetics. `Prose` provides a designated container class that cascades our typographic scales specifically onto its raw nested children.

### Long-Form Reading Architecture
Unlike the `Text` component (which is optimized for interface density), `Prose` specifically architects itself for long-form narrative consumption:
1. **Extended Rhythms:** It targets internal paragraphs and overrides standard padding with larger, relaxed vertical margins (`var(--space-6)`).
2. **Reading Leading:** The line height is aggressively loosened (e.g., `line-height: 1.8`) to prevent text block fatigue during deep-dive technical articles.
3. **Typography Scope Capture:** By strictly scoping the child selectors (e.g., `.prose h2`), it guarantees that article styling cannot bleed out and affect the broader page's navigational header elements.
