wReady is a beautiful, minimal, and highly performant personal creative workbench designed to organize, write, and manage creative work across diverse formats—screenplays, songs, poems, and short stories. Leaning into a file-based, local-first workflow, all content lives as version-controlled MDX files inside Astro Content Collections, validated strictly with Zod schemas.

Rather than a public blog or standard CMS, wReady is designed from the ground up as a focused, developer-centric creative writing environment, maximizing speed, design aesthetics, and offline reliability.

## Technical Architecture & Design Philosophy

When building a modern web application, developers often default to heavy, JavaScript-saturated Single Page Applications (SPAs) like React or Next.js. While these frameworks are excellent for highly dynamic dashboards, they come with a steep performance tax: shipping megabytes of client-side JavaScript that the browser must download, parse, and execute before the page becomes interactive.

For wReady, I wanted to prove that **creative and editorial tools can be incredibly fast, static, and highly interactive without the bloat**. To achieve this, the architecture is built around a hybrid, static-first philosophy:

1. **Astro 6 (Static Engine)**: Astro acts as the compiler. At build-time, it compiles our raw markdown files, layouts, and components into pure, semantic HTML and CSS. The client receives **zero bytes of JavaScript by default**, ensuring perfect Largest Contentful Paint (LCP) and immediate layout stability.

2. **Alpine.js (Lightweight Interactivity)**: When a feature absolutely requires dynamic client-side state, we pair Astro with Alpine.js to add micro-interactions with negligible footprint.

3. **Vanilla CSS**: Leverages custom properties (design tokens) to establish a highly customized, distraction-free typographic system suited for long-form reading and writing.

## Introducing Alpine.js: Rugged Interactivity

To bring features like the Chord Analyzer and character filter list to life, I integrated [Alpine.js](https://alpinejs.dev/). 

### What is Alpine.js?
Alpine.js is a minimal, expressive frontend framework that provides the reactive power of major frameworks like Vue or React, but at a fraction of the cost (just **~15KB gzipped**). Instead of forcing us to build complex virtual DOM trees, write state selectors, or manage virtual state layers, Alpine allows us to write behavior **directly in our markup** using simple HTML data attributes (like `x-data`, `x-bind`, and `x-on`).

In wReady, Alpine.js handles:
* **Fretboard State**: Tracking which string and fret a user clicks in real-time.
* **Filter Matrices**: Instantly showing or hiding scene cards based on active character selections, without triggering a server query or causing layout shifts.
* **Dynamic Calculations**: Translating note indexes dynamically while displaying chord structures.

This lets us build highly interactive editorial interfaces while preserving Astro’s fast, lightweight DOM architecture.

## The Screenplay AST Engine

One of the primary engineering challenges in writing screenplays in Markdown is formatting. Traditional screenplays require rigid, highly specific alignments: character names centered, parentheticals indented, and dialogue restricted to narrow gutters. Manually wrapping each element in HTML tags or JSX classes makes rapid drafting impossible and completely breaks the creative flow state.

To solve this, I wrote a custom build-time **Remark plugin** (`remark-screenplay.ts`). This plugin intercepts the Markdown Abstract Syntax Tree (AST) at compile time. It scans the document and transforms a customized shorthand syntax into styled MDX components:

### The Syntax Shorthand
- `s- INT. LENNON'S FLAT - DAY` → Renders a `<Scene>` break
- `c- LENNON` → Renders the `<Character>` speaker anchor
- `p- (grinning)` → Renders dynamic `<Parenthetical>` expressions
- `d- Imagine there's no countries...` → Renders speaker-assigned `<Dialogue>`

### Implicit Formatting Support
To make drafting even faster, the plugin supports **implicit line parsing**. If the plugin detects a standard text line matching screenwriting conventions, it formats it automatically:
1. **Implicit Character**: A line written in ALL CAPS (e.g. `LENNON`) is automatically parsed as a `<Character>` block.
2. **Implicit Parenthetical**: A line wrapped in parenthesis `(like this)` within dialogue is treated as a `<Parenthetical>` block.
3. **Implicit Scenes**: A line starting with `INT.`, `EXT.`, or `INT/EXT` is automatically normalized and parsed as a `<Scene>` header.

Here is the recursive AST traversal logic from the parser:

```typescript
// Excerpt from remark-screenplay.ts
export const remarkScreenplay: Plugin<[], Root> = () => {
  return (tree, file) => {
    visit(tree, "paragraph", (node: Paragraph) => {
      const rawText = node.children
        .filter((child): child is Text => child.type === "text")
        .map((child) => child.value)
        .join("");

      // Implicit character line: ALL CAPS name
      if (isImplicitCharacterLine(rawText)) {
        flushDialogue();
        inDialogue = true;
        currentCharacter = rawText.toUpperCase();
        dialogueBuffer.push(jsx("Character", currentCharacter));
        return;
      }

      // Implicit parenthetical inside dialogue
      if (inDialogue && isImplicitParentheticalLine(rawText)) {
        dialogueBuffer.push(
          jsx("Parenthetical", stripOuterParens(rawText), { speaker: currentCharacter })
        );
        return;
      }
      
      // Implicit scene header check
      if (isImplicitSceneLine(rawText)) {
        flushDialogue();
        newChildren.push(jsx("Scene", normalizeSceneHeading(rawText)));
        return;
      }
    });
  };
};
```

This transforms raw Markdown files into a beautifully formatted, standardized screenplay view with an interactive current-line highlighter and a side-by-side editing canvas:

## Mathematical Music Theory & Diatonic Chords

wReady includes a powerful suite of songwriting features designed around **music theory mathematics**.

Instead of hardcoding a massive database of static guitar chord images, wReady calculates chords dynamically using **semitone intervals** (relative distances between notes). In the standard chromatic scale, there are 12 notes. By representing notes as numeric values from `0` to `11` (where C is 0, C# is 1, etc.), we can mathematically define any scale or chord formula:

```typescript
// excerpt from src/utils/music/musicTheory.ts
export const INTERVALS = {

  m2: { name: 'Minor 2nd', shortName: 'b2', semitones: 1 },
  M2: { name: 'Major 2nd', shortName: '2', semitones: 2 },
  m3: { name: 'Minor 3rd', shortName: 'b3', semitones: 3 },
  M3: { name: 'Major 3rd', shortName: '3', semitones: 4 },
  P4: { name: 'Perfect 4th', shortName: '4', semitones: 5 },
  TT: { name: 'Tritone', shortName: 'b5', semitones: 6 },
  P5: { name: 'Perfect 5th', shortName: '5', semitones: 7 },
  m7: { name: 'Minor 7th', shortName: 'b7', semitones: 10 },
  M7: { name: 'Major 7th', shortName: '7', semitones: 11 },
};

export const CHORD_FORMULAS = [
  { name: 'Major', abbreviation: '', intervals: [0, 4, 7], quality: 'major' },
  { name: 'Minor', abbreviation: 'm', intervals: [0, 3, 7], quality: 'minor' },
  { name: 'Dominant 7th', abbreviation: '7', intervals: [0, 4, 7, 10], quality: 'dominant' },
  { name: 'Minor 7th Flat 5', abbreviation: 'm7b5', intervals: [0, 3, 6, 10], quality: 'diminished' },

```

By querying these vectors, wReady renders interactive fretboard fingerings, translates keys, and maps diatonic chords (e.g. `I, ii, iii, IV...`) to songwriting templates, facilitating creative melody drafting.

## TMDB API Integration & Data Enrichment

To enrich review columns (such as film, book, and television write-ups), I engineered automated data pipelines (`enrich-tmdb.ts` & `enrich-actors.ts`).

### The Data Automation Flow
Instead of manually copy-pasting metadata, bios, and image directories, the pipeline utilizes a zero-friction local-enrichment script:
1. **Source Discovery**: The Node script parses the frontmatter of newly written Markdown files using a YAML parser.
2. **TMDB Query**: It extracts the TMDB identifier and queries the **TMDB REST API** endpoints (specifically `/movie/{id}` or `/tv/{id}/credits`).
3. **JSON Extraction**: The script extracts cast profiles, official poster artwork directories, director credentials, and community ratings.
4. **Write-Back**: The script rewrites the YAML frontmatter of the local Markdown file, injecting the enriched TMDB data directly.
5. **Static Compilation**: Because this is executed locally prior to build, Astro compiles these parameters into ultra-fast, pre-rendered, completely static HTML pages during build, with zero client-side fetching!

```bash
# Automate review metadata enrichment
pnpm run tmdb
```
